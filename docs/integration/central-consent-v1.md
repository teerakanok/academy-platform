# Central consent in the Academy dashboard

Identity owns the two canonical purposes and append-only events. Academy displays its response and delegates only state reads and withdrawals. Existing Academy mailing-list consent records are independent legacy records; neither email matches nor pending waitlist requests populate central consent.

The producer contract is Identity `packages/contracts/src/consumer-consent.ts`, version1, SHA256 `6e82c9ee7b21a4f0028f4c434e02400b458562e4b910777d5c85f0e83f1d74e0`. Public fixture bytes have SHA256 `651c43d5da68437cbbebb5ec42ac16752c13d553ecb1a05d30427a61a97a196c`. These contain synthetic principals and public verification material only.

Browser POST `/api/account/consents/state` accepts exactly `{}`; `/withdraw` accepts exactly `{type,operationId,expectedRevision}`. Existing same-origin/Fetch Metadata validation, edge marker, bounded body, durable opaque session and account quota apply. The BFF derives issuer and subject from the active server session. It rejects a legacy direct-OTP fixture and any noncanonical issuer. Local account ID is only a quota key. No email or browser-supplied principal is authority.

The dedicated ES256 JWT uses `identity-consent-delegation-v1+jwt`, purpose `consent.state` or `consent.withdraw`, and the exact pinned HTTPS endpoint audience. A new random jti is minted per attempt, with a60-second assertion lifetime. SHA256 requestDigest covers exactly `[1,"POST",path,"academy-web",issuer,subject,typeOrNull,operationIdOrNull,expectedRevisionOrNull]`. The admitted production signer configuration is reused, while code-exchange assertion claims and provider remain unchanged. The upstream request has only JSON Content-Type and its own Authorization header, no browser cookies or Origin. Redirects are forbidden; request, total transport deadline and response are bounded. Responses require no-store and no Set-Cookie. Identity rechecks client key, activation and canonical principal.

Withdrawals preserve operationId and expectedRevision on an uncertain retry. A409 returns canonical current state and clears the old intent. The UI never automatically replaces the revision and resubmits. A fresh withdrawal requires another explicit confirmation. Failures display unknown/unconfirmed status, never a fabricated OFF or completed state. Successful responses and reloads use producer readback. Grants remain in Identity's own consent flow.

Verification: dedicated route tests reject forged principal fields, missing session, wrong issuer, cross-site requests and exhausted quota. Transport tests bind signed tuples to producer fixtures, verify real ES256 signatures, and reject malformed/duplicate JSON, oversized responses, redirects, Set-Cookie and absent no-store. Rejected and delayed response bodies are cancelled; hung fetch/body deadlines fail closed. The malformed decimal revision regression was reproduced before guarding BigInt conversion.

Local rendered fixture: run Vite with `tests/fixtures/consent-vite.config.mjs`, then `node tests/fixtures/consent-browser.mjs <owned-absolute-evidence-directory>`. This imports the actual component/client and mocks only local BFF responses. It covers TH/EN, light/dark,390/1365 widths, both purposes, failed withdrawal, same-intent retry,409, fresh confirmation, persisted reload, unavailable and loading. It is synthetic evidence, not authenticated owner acceptance. No fixture route is added to the production Next app.

Deployment requires the producer's dedicated routes, replay store and revision CAS implementation to be deployed first with Academy's registered key authorized for these purposes. Academy uses its existing admitted runtime configuration and fixed production endpoints; no new credentials or direct Identity database grants are needed. Until the producer is ready, the panel truthfully reports unavailable. Follow the existing backup/restored rehearsal/apply/readback/rollback release sequence; this document grants no live authority.
