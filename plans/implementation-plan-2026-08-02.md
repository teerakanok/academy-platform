## 1. หลักที่ทุกงานต้องเคารพ

### 1.1 คูเมืองคือ "การร้อยกัน" ไม่ใช่ชิ้นส่วนใดชิ้นเดียว
*(founder แก้จุดเน้น 2026-08-02 — กำหนดลำดับงานทั้งแผน)*

lab อย่างเดียวไม่ใช่จุดต่าง แพลตฟอร์มอื่นก็มี สิ่งที่ลอกยากคือการที่
**วิดีโอ + คำถามคั่น + checkpoint + simulation + lab อยู่บนแกนเดียวกัน** โดยมี
progress และหลักฐานวิ่งผ่านทุกชิ้นสะสมขึ้นเป็นแผนที่ทักษะเดียว
คนที่ดูดข้อความหรือวิดีโอไปได้ **ชิ้นส่วน** — สิ่งที่เราขายคือ **เส้นทาง**

> **"รอยต่อที่ยังไม่เชื่อม" มีค่ากว่า "ชิ้นส่วนใหม่"** — และ **"รอยต่อที่รั่ว" ต้องซ่อม
> ก่อนต่อรอยต่อใหม่**

### 1.2 client ส่งได้แค่ "สิ่งที่ทำ" ห้ามส่ง "ผลลัพธ์" — และ **ห้ามเห็นเฉลย**
เกณฑ์ตรวจตัวเองสองข้อ:
1. ถ้าลบ UI ทิ้งแล้วยิง curl ตรงๆ ได้ผลเดียวกัน = **ปลอมผลได้**
2. ถ้าเปิด view-source แล้วเห็นคำตอบ = **ไม่ต้องปลอมก็ผ่านได้** ← ข้อนี้ร่างแรกมองข้าม

### 1.3 สี่ชั้นสถานะ ชั้นก่อนหน้าไม่เคยแปลว่าได้ชั้นถัดไป
```
account exists → service activation → product entitlement → resource authorization
```

### 1.4 ล็อก ≠ มองไม่เห็น · ล็อก ≠ ไปไม่ถึง
บทที่ล็อกต้องบอก: ชื่อ · สาระที่ครอบคลุม · เวลา · **ทำไมล็อก** · **ทำอะไรถึงเปิด**
และมีปุ่ม "ฉันรู้อยู่แล้ว ขอพิสูจน์เลย" เสมอ
เหตุผล: **การแอบดูคือข้อมูลที่ใช้ตัดสินใจ ไม่ใช่ทางลัด**

### 1.5 ภาษาไม่ปนกัน
เว็บอังกฤษห้ามมีคำไทยและกลับกัน · ⚠️ เทสปัจจุบัน (`tests/unit/i18n.test.ts`) ตรวจ
**เฉพาะ dictionary** ไม่ตรวจข้อความที่ hardcode ใน JSX หรือ error จาก API →
งานใหม่ต้องเพิ่มข้อความลง dictionary เท่านั้น ห้าม hardcode

#### W0-0 · โครง attempt + คลังข้อ 🔴 **ต้องเสร็จก่อน W0-1**
> RIL รอบ 4 ชี้ว่าลำดับเดิมเดินไม่ได้: W0-1 อ้างถึง "หมุนโจทย์ใหม่ต่อ attempt" แต่กลไก
> attempt ทั้งหมดเคยอยู่ใน W1 — จึงย้ายขึ้นมาเป็นงานแรกจริงๆ

**1. โครง attempt** (เดิมอยู่ใน W1 ย้ายมาที่นี่ เพราะทั้ง MCQ และ simulation ใช้ร่วมกัน)

| field | หน้าที่ |
|---|---|
| `attempt_id` | คีย์ของความพยายามครั้งนี้ · เดาไม่ได้ |
| `user_id` + `course_slug` + `node_id` + `challenge_id` | ผูกว่าเป็นของใครบทไหน — ส่ง attempt ของคนอื่น/บทอื่นมาใช้ไม่ได้ |
| `params` | ชุดข้อ/ลำดับตัวเลือก/ค่าเป้าหมายที่สุ่มมา (เซิร์ฟเวอร์ถือฝ่ายเดียว) |
| `challenge_version` | เวอร์ชันของโจทย์ ณ ตอนออก attempt — ใบรับรองอ้างถึงได้ |
| `expires_at` | หมดอายุ (ค่าเริ่มต้น 60 นาที) |
| `consumed_at` | ใช้แล้วใช้ซ้ำไม่ได้ (กัน replay) |

flow: `POST /api/attempts` → ได้ `attempt_id` + โจทย์ที่สุ่มแล้ว → ผู้เรียนทำ →
`POST /api/progress {action:'checkpoint', attemptId, ...}` → เซิร์ฟเวอร์ตรวจจาก
`params` ที่ตัวเองถือ

⚠️ **consume ต้อง atomic และเงื่อนไขทั้งหมดต้องอยู่ใน `WHERE` เดียวกัน** —
```sql
update academy.attempt set consumed_at = now()
 where attempt_id = $1 and user_id = $2
   and course_slug = $3 and node_id = $4 and challenge_id = $5
   and consumed_at is null and expires_at > now()
returning params, challenge_version
```
ถ้าอ่านก่อนแล้วค่อยเขียน สอง request ที่ยิงพร้อมกันจะผ่านทั้งคู่ · ถ้าตรวจ ownership
นอก `WHERE` คนอื่นจะ consume attempt ของเราทิ้งได้ — **บั๊กชนิดเดียวกับที่เคยเจอใน
`record_node_progress`** ซึ่งแก้ด้วยการย้ายเงื่อนไขลงไปในคำสั่งเดียวของฐานข้อมูล

#### W0-3 · `completed` ต้องแปลว่าพิสูจน์แล้ว (แก้ F2 + F3)
ปัญหา: บทปกติผ่านด้วย "ตอบครบ" · `certificateEligibility` นับ `completed` เป็น proven
→ **ตอบผิดทุกข้อแล้วได้ใบรับรอง**

**ล็อกทางเลือกแล้ว — implement ได้เลย ไม่ต้องรอ**

**(1) บทปกติต้อง `ผิดได้ไม่เกิน 1 ข้อ` ถึงได้ `completed` · retry ไม่จำกัด**
- retry ไม่จำกัดรักษาท่าที "ตอบผิดไม่ใช่บทลงโทษ" ไว้ครบ
- เกณฑ์ "ผิดได้ไม่เกิน 1" ทดสอบได้ตรงๆ และใช้ได้กับ checkpoint 3–5 ข้อเหมือนกันหมด
- founder เปลี่ยนตัวเลขได้ทีหลัง — เป็นค่าคงที่ที่เดียว

**(2) ⚠️ ยอมรับตรงๆ ว่า `completed` ของบทปกติ ≠ "พิสูจน์แล้ว"** — RIL รอบ 5 ชี้ถูก
โหมด learn บอกผลรายข้อ + `explanation` **และ retry ไม่จำกัด** → บทปกติมี 3 ข้อ ×
4 ตัวเลือก ไล่ลองไม่กี่รอบก็ผ่านโดยไม่ต้องรู้เนื้อหา · **นี่ไม่ใช่บั๊ก มันคือธรรมชาติ
ของโหมดสอน** จะปิดก็ต้องทิ้ง feedback ที่เป็นหัวใจของการเรียนไป

**ทางออกที่ล็อก: ย้ายน้ำหนักของใบรับรองไปที่ capstone ทั้งหมด**
- `completed` (บทปกติ) = "ทำครบและตอบผ่านเกณฑ์" → ใช้เป็น**เงื่อนไขความคืบหน้า**เท่านั้น
- **หลักฐานที่ใบรับรองอ้างถึง = capstone ทุกจุดผ่านแบบ assessed** (และ `tested-out`
  ซึ่งก็เป็น assessed) — สองอย่างนี้ถูก harden แล้วใน W0-0/W0-1
- แก้ `certificateEligibility` (`roadmap.ts:239`) ให้แยกสองเงื่อนไข:
  ทุก node ต้อง `completed`/`tested-out` **และ** ทุก capstone ต้องผ่านแบบ assessed
- **ห้ามเขียนบนหน้าเว็บหรือบนใบว่าบทปกติเป็นการวัดผล** — เขียนตามจริงว่าใบรับรอง
  ยืนยัน capstone

⚠️ เกณฑ์รับงานต้องเป็นเทสแบบ **"ไล่ลองจนผ่าน"** ไม่ใช่ยิงครั้งเดียว —
เทสที่ยิงผิดครั้งเดียวแล้วเช็คว่าไม่ผ่าน จะ **เขียวทั้งที่ลูป brute-force ยังเปิดอยู่**

#### W0-4 · นิยามบทบาทของคำถามกลางวิดีโอให้ชัด (แก้ F5)
ตอนนี้ตรวจและบันทึกจริง แต่ไม่ถูกใช้ตัดสินอะไร
**ล็อกแล้ว: เป็น formative ไม่ใช่หลักฐาน**
คำถามกลางวิดีโอมีไว้ให้คนตื่นตัวและจับว่าเข้าใจผิดตรงไหน ไม่ใช่ด่าน — ถ้าทำให้เป็นด่าน

→ งานที่ต้องทำ: **แก้เอกสารทุกที่ที่เรียกมันว่า "แกนหลักฐาน"** ให้ตรงความจริง
(รวมถึง §2.1 ของแผนนี้เอง และ `plans/active_plan.md`) และคงการบันทึกผลไว้เพื่อใช้

### W1 — ต่อ simulation เข้าแกนหลักฐาน 🔴

**ทำหลัง W0 เท่านั้น** (W1 ใช้โครง attempt ของ W0-0 ตรงๆ ไม่สร้างของตัวเอง)

#### ขอบเขต
1. `CheckpointItem = McqItem | SimulationItem` (discriminated union)

2. progress API: action `checkpoint` รับ `mcqAnswers` + `simulationSubmissions`

4. เก็บหลักฐาน: ขยาย `node_progress` (หรือตารางใหม่) ให้บันทึก **ผลราย requirement +
   เวอร์ชันของ challenge + เวลา** — ไม่ใช่แค่ boolean รวม
   *เหตุผล: ใบรับรองอ้างอิงหลักฐานนี้ ต้องตรวจย้อนหลังได้ว่าผ่านด้วยอะไร*

#### ⚠️ ข้อจำกัดที่ต้องยอมรับและเขียนไว้ให้ชัด
RIL ชี้ว่า **การรับ "สถานะสุดท้าย" จาก client แปลว่า curl ยิงตรงก็ผ่านได้** โดยไม่ต้อง
เปิดหน้าจอเลย ซึ่งจริง

**ทางเลือกที่ประเมินแล้ว:**
- *(เลือกอันนี้)* **สุ่มพารามิเตอร์ต่อ attempt** — เซิร์ฟเวอร์สร้างโจทย์ที่ค่าเป้าหมาย
  ต่างกันทุกครั้ง (เช่น IP เป้าหมายสุ่มจาก seed ที่เซิร์ฟเวอร์ถือ) → คำตอบแชร์กันไม่ได้
  และอ่านจากคำตอบของคนอื่นไม่ได้ ต้องอ่านโจทย์ของตัวเองแล้วคิดเอง

  ใช้ **โครง attempt ของ W0-0** ทั้งหมด (`attempt_id` · ownership ใน `WHERE` ·
  `params` · `expires_at` · atomic consume) — W1 เพิ่มแค่ว่า `params` ของ simulation
  คือค่าเป้าหมายที่สุ่ม (เช่น IP ปลายทาง) และเซิร์ฟเวอร์คำนวณเกณฑ์ผ่านจากตรงนั้น
- *(ไม่ทำตอนนี้)* เซิร์ฟเวอร์ถือ state แล้วรับเฉพาะ action ทีละขั้น — ถูกต้องที่สุดแต่
  เป็นงานใหญ่ (attempt session, action log, replay) **ทำเมื่อ simulation กลายเป็นด่าน
  ของ certification จริง ไม่ใช่ตอนนี้**
- **บันทึกไว้ให้ชัดว่า**: simulation checkpoint พิสูจน์ว่า *"รู้คำตอบที่ถูก"*
  ไม่ใช่ *"ลงมือทำจริง"* — อย่าเคลมเกินนี้บนหน้าเว็บหรือบนใบรับรอง

### 10.5 รอบที่ 5 — codex + Claude critic (NEEDS-WORK ทั้งสองเลน · แก้ครบแล้ว)
