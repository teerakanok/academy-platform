# เกตตรวจข้อเท็จจริงของเนื้อหาคอร์ส

บทเรียนสอนคำสั่งและตัวเลขที่ผู้เรียนจะพิมพ์ตามจริง ข้ออ้างพวกนี้จึง **ตรวจได้ด้วยการรัน**
ไม่ใช่ด้วยการอ่านทาน ไฟล์ในโฟลเดอร์นี้รันข้ออ้างเหล่านั้นกับเครื่องมือตัวจริง แล้วเทียบผล

```
bash tests/factcheck/run-all.sh
```

| ไฟล์ | ครอบอะไร | ต้องมีอะไร |
|---|---|---|
| `c-claims.c` | ทุกตัวเลข/ผลลัพธ์ที่คอร์ส C อ้าง — เลขจำนวนเต็ม, บิต, ทศนิยม, ขนาด struct, พอยน์เตอร์ | C compiler |
| `git-claims.sh` | เดินตาม try step ของคอร์ส Git ใน repo ทิ้ง — รวม conflict, rebase, reflog, worktree, hook, remote จริง | git |
| `linux-claims.sh` | คำสั่งของคอร์ส Linux — grep/sed/awk/pipeline/permission/สคริปต์/signal/cron/ssh | docker (รันบน Debian จริง ไม่ใช่ BSD tools ของ macOS) |

## กฎเมื่อเกตแดง

ก่อนแก้ ให้ตัดสินก่อนว่าอะไรผิด — **บทเรียน** หรือ **ความคาดหวังในเกต** พิสูจน์ด้วย
minimal reproduction แยกต่างหาก แล้วค่อยแก้ฝั่งที่ผิดจริง ห้ามแก้ตัวเลขในเกตให้เขียวเฉย ๆ

ตัวอย่างของจริงที่เกตนี้จับได้ตอนสร้าง:

- คอร์ส C อ้างว่า `printf("%.10f", total)` ของผลรวม 1000×0.01 พิมพ์ `9.9999999999`
  ค่าจริงคือ `10.0000000000` เพราะ printf ปัดให้ ต้องใช้ `%.15f` ถึงเห็น `9.999999999999831`
  — ประเด็นที่สอนถูก แต่ตัวเลขที่โชว์ผิด และการปัดของ printf กลายเป็นบทเรียนที่ดีกว่าเดิม
- คอร์ส Git มี try step ที่สั่ง `git commit --allow-empty` แล้วตามด้วย `git commit --amend -m`
  ซึ่ง **ล้มเหลวจริง** ("doing so would make it empty") ผู้เรียนที่ทำตามจะติดตรงนั้น

## เมื่อเพิ่มคอร์สใหม่

คอร์สที่สอนคำสั่งหรือตัวเลขต้องมาพร้อมข้ออ้างในไฟล์เหล่านี้ก่อนถือว่าเสร็จ

## arch-claims.sh — ตัวเลขที่ขึ้นกับเครื่อง

คอร์ส computer-architecture อ้างตัวเลขที่วัดจากเครื่องผู้เขียน (6.94x, 4.00x,
1.94x) ตัวเลขเหล่านี้**ต่างกันตามฮาร์ดแวร์** เกตจึงตรวจสองอย่างแยกกัน:

- **ข้ออ้างที่คำนวณได้** (เลขคณิตของสายพาน, การเข้ารหัส RISC-V) ตรวจแบบเป๊ะ
  ผิดหนึ่งบิตคือบทเรียนผิด
- **ข้ออ้างที่วัดได้** ตรวจแค่ทิศทางและขนาดขั้นต่ำ เพราะการ pin ตัวเลขของ
  เครื่องหนึ่งไว้คือการทำให้เกตโกหกบนเครื่องอื่น เกตพิมพ์ค่าที่วัดได้จริง
  คู่กับค่าที่บทเรียนอ้าง ให้คนอ่านเทียบเอง

ข้อ `-O2 กลายเป็นการเทียบแบบเวกเตอร์` ผูกกับคอมไพเลอร์และสถาปัตยกรรม
ถ้ามันล้มเหลวบนเครื่องอื่น **อย่าลบข้ออ้างออกจากบทเรียน** — บทรวบยอดสอน
วิธีตรวจ assembly ด้วยตัวเองอยู่แล้ว ให้ตรวจว่ากิ่งถูกกำจัดด้วยวิธีอื่น
(เช่น conditional select) หรือไม่ แล้วขยายเกตให้รับรูปแบบนั้นด้วย

## asm-claims.sh — ข้ออ้างที่ผูกกับคอมไพเลอร์

คอร์ส assembly ยกผลจากคอมไพเลอร์มาเป็นหลักฐาน เกตจึงคอมไพล์ซอร์สเดียวกัน
แล้วตรวจว่ารูปแบบที่บทอ้างยังปรากฏจริง (x/10 ไม่มีคำสั่งหาร, x*9 เป็น lea
ตัวเดียว, setl เทียบ setb, struct 32 ไบต์เขียนผ่าน rdi, canary ขึ้นเฉพาะ
ฟังก์ชันที่มีอาร์เรย์ ฯลฯ)

ผลเหล่านี้**ผูกกับคอมไพเลอร์และรุ่นของมัน** ถ้าข้อไหนล้มเหลวบนเครื่องอื่น
ให้ตัดสินก่อนว่าคอมไพเลอร์เปลี่ยนพฤติกรรม หรือบทเรียนผิด — **ห้ามลบข้ออ้าง
ออกจากบทเรียนเพื่อให้เกตเขียว** บทเรียนสอนวิธีตรวจ assembly ด้วยตัวเองอยู่แล้ว
สิ่งที่ถูกต้องคือปรับข้อความในบทให้ตรงกับสิ่งที่คอมไพเลอร์ทำจริงในวันนี้
